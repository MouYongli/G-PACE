# GRACE

Research repository for GRACE, worked on by Codex and Claude Code sessions in manager and worker roles. This checkout (the main checkout, `PROJECT_ROOT`) stays on `main`; managers and workers each work in their own git worktree. Work is planned as a DAG of milestones, tasks, experiments and decisions in `docs/work/plan/plan.yaml`.

## Getting started

1. Read `AGENTS.md` (Chinese translation: `AGENTS.zh-CN.md`) and `docs/README.md`.
2. Read the research plan `docs/research/plan.md` (Chinese translation: `docs/research/plan.zh-CN.md`).
3. Bind the benchmarks: fill in `configs/benchmarks/<slug>.yaml` and the cards in `docs/research/benchmarks.md`.
4. Download the benchmarks into `data/<benchmark>/<version>/` in this checkout with `scripts/data/download.sh` (see [Benchmarks](#benchmarks)), then make them read-only with `chmod -R a-w data`. Create `runs/`. Both are git-ignored; every worktree finds them through `PROJECT_ROOT` (see `AGENTS.md`). CI uses the synthetic fixtures in `tests/fixtures/`.
5. Install [uv](https://docs.astral.sh/uv/), then run `make setup`, `make test` and `make lint` (Python 3.12, CPU only). On the GPU machine, also run `make setup-serve` and start model servers with `scripts/serve-model.sh` (see decision D004).
6. On GitHub, add branch rules for `main` and `task/*`: require PRs, the `contracts` and `lint` status checks, and an up-to-date base.
7. Open the plan viewer (see `docs/README.md`), create an Issue for each task you start, record it in `plan.yaml`, and start each manager session in its own worktree with the `start-manager` skill.

## Benchmarks

Six benchmarks, registered in `docs/research/benchmarks.md` with their role in the plan. Five are downloaded at pinned revisions; the controlled change sequences are generated by the project.

| Script | Slug | Benchmark and files | Source (pinned revision) | Size | Licence |
| --- | --- | --- | --- | --- | --- |
| `b1_multiwoz.sh` | `multiwoz` | MultiWOZ 2.4 (main scoring), 2.2 (dev, test, dialogue acts, schema) and 2.1 (comparison with published zero-shot results); the same test dialogues in three annotation versions | GitHub `smartyfh/MultiWOZ2.4`, `budzianowski/multiwoz` | 0.8 GB unpacked | MIT (repositories) |
| `b2_locomo.sh` | `locomo` | LoCoMo `locomo10.json` (10 histories, 1,986 questions) plus the independent audit's per-conversation error lists | GitHub `snap-research/locomo`, `dial481/locomo-audit` | 3 MB | CC BY-NC 4.0 |
| `b3_longmemeval-s.sh` | `longmemeval-s` | LongMemEval-S cleaned (500 questions, about 115K tokens of history each) and the oracle file | Hugging Face `xiaowu0162/longmemeval-cleaned` | 280 MB | MIT |
| `b4_halumem-medium.sh` | `halumem-medium` | HaluMem-Medium (20 users, gold memory points and update labels) | Hugging Face `IAAR-Shanghai/HaluMem` | 32 MB | CC BY-NC-ND 4.0 |
| `b5_memoryagentbench.sh` | `memoryagentbench` | MemoryAgentBench files holding LongMemEval(S\*) and FactConsolidation | Hugging Face `ai-hyz/MemoryAgentBench` | 21 MB | MIT |
| — | `change-seq` | Controlled change sequences, generated (design: task T008) | — | — | — |

Download all of them, or one at a time, from the main checkout:

```bash
scripts/data/download.sh               # every benchmark, in the order above
scripts/data/b2_locomo.sh              # one benchmark
scripts/data/download.sh --dry-run     # list URLs and targets without downloading
chmod -R a-w data                      # afterwards: the store is read-only
```

- Sources, revisions and expected checksums live in `configs/data/sources.yaml`; the scripts call `src/grace/cli/data/download.py`.
- Each version lands in `data/<slug>/<version>/` with `MANIFEST.sha256` (SHA-256 of every data file) and `SOURCE.json` (sources, URLs, licence, retrieval time). Files with a registered checksum and the manifest itself are checked after download; a mismatch aborts and leaves nothing behind.
- An existing version is never overwritten: rerunning verifies its manifest instead. To add a version after the store was made read-only, make `data/<slug>` writable for the download and read-only again afterwards.
- Licences limit redistribution (LoCoMo non-commercial; HaluMem no derivatives). Publish split lists and scripts, never re-annotated data.
